# 核爆分帧优化与实测 — 2026-10-09

版本：0.1.2（Factorio 2.0.77）、0.1.3（Factorio 2.1.21 experimental）。无 Space Age。

## 结果

旧实现已有原生弹道传播，但引爆帧一次性创建满电的 200,000 个伤害弹道，造成明显停顿。新实现把伤害弹道放入持久队列，每 tick 全局最多调度 1,024 个。没有提高单次伤害、降低总数量或替换成大型瞬时 area damage。

对照在补充整数阈值修正前进行；满电阈值本来就是整数，分帧调度代码相同。最终整数版另有核爆回归日志，未将并行回归的耗时当作下面的独立性能对照。

相同主机、相同 3,200 tick 场景、相同运行时验收脚本，旧版与新版依次运行（性能对照没有并行运行）。两边都独立创建和加载存档，Space Age 等 DLC 禁用。场景包含 0%、50%、100% 爆炸、连锁爆炸、实际墙体损伤，以及后续 D 引爆。

| 引擎 | 旧版最大单 tick | 新版最大单 tick | 峰值降低 | 旧版平均 | 新版平均 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2.0.77 | 1,347.765 ms | 132.152 ms | 90.19% | 31.742 ms | 15.806 ms |
| 2.1.21 | 1,467.251 ms | 166.427 ms | 88.66% | 34.497 ms | 14.725 ms |

这是该场景各一次运行的实测，系统调度和随机空间分布会影响结果，不保证所有电脑得到同样值。新版延长释放过程；固定 tick 窗口的平均值不等于完整爆炸总计算量降低相同比例。峰值仍高于 16.7 ms，不能宣称稳定 60 UPS。在途原生弹道仍然消耗 CPU。

## 数量、伤害与分帧架构

- 所有 101 档仍为 M=1+9×电量档/100；半径 R0×M；每道总数 round(N0×M²)。当前原版两道 N0 均为 1,000，满电各 100,000，共 200,000。
- 原生 3 格局部伤害半径、100/400 explosion 基础伤害、starting_speed、速度偏差、acceleration、speed_modifier、原版目标规则和友军伤害保留。距离衰减阈值按倍率扩展后显式四舍五入为整数；其 uint16 字段带来最多 0.5 格的阈值舍入误差，0%/100% 的阈值无舍入误差。
- 每道波使用 512 的完整批次和实际余数尾批；数据阶段逐档断言精确总数及原版参数。小批次用于帧调度；区域行动 repeat_count 实际为 uint32，不是历史说明中的 uint16。
- 可见中心/附加效果载体不再生成两道主要伤害波；它们只能由批次发射载体生成。视觉数量没有乘以面积倍率。
- Lua 每 tick 只取一个队列任务，创建最多两个隐藏原生发射载体，然后将未完成任务放回队尾。没有逐 tick 扫描地图、遍历受伤区域或逐个运算 20 万弹道。
- 所有本 Mod 的连锁爆炸共享额度且公平轮询；无限制保留任务，不人为截断连锁或伤害总量。
- 单座满电需要 ceil(100000/512)=196 tick（约 3.27 秒游戏时间）释放；弹道继续从原中心以原版速度传播。
- 相比一次性原版脉冲，近处后续伤害持续更长，波前变宽。这是明确的时间分布变化；总体空间分布与密度仍采用原生 area 规则。
- 旧 0.1.0/0.1.1 存档若保存了尚未命中的核爆载体，配置升级会读取其名称中的电量档并转入队列，避免载体变成仅视觉效果后漏掉伤害。
- 保存 storage 中的队列、剩余数量、阵营和地表引用；原生在途弹道由引擎保存。阵营合并时迁移队列阵营，删除地表时丢弃失效任务，完成后重置队列索引。

## 实际验收

两版源码完成以下运行并检查退出码和完成标记；补充整数衰减阈值修正后，两版再运行核爆验收，日志为 final-integer-falloff/：

- 3,200 tick 电网与核爆验收：36 GJ、双向 5 MW、真实雷达耗能、E/H/P、0/50/100% 范围、原生传播、友军损伤、连锁和 D 引爆；新增满电完好近/远目标到达时间。
- 4,900 tick 原生机器人生命周期回归：建造、回收、防刷电、回收版放置、蓝图、实际采矿机供电、雷达扫描和 helper 清理。
- 新增真实连锁调度计数断言：满电源站和空电次级站的合计恰好 200,000+2,000 个，新增释放任务数恰好两个，避免仅以“次级站被摧毁”代替二次爆炸证据。
- 350 tick 队列场景：同时放入 0%、50%、100% 爆炸、一次阵营合并和一个删除地表的任务。逐 tick 检查调度增量 <=1,024；有效四个任务最终恰好 264,500 个伤害弹道，completed=4、queued=0。completed 指释放完成，原生在途弹道仍可能尚未命中。
- 私有 localhost headless 服务器：在爆炸部分释放后实际写出存档，再用该存档运行 350 tick；剩余队列与最终精确总数仍正确。服务器没有公开发布或接入客户端。
- 旧版升级真实存档测试：在旧代码中实际建立带未命中核爆载体和约 17.123 GJ 电池的存档，换为新版本载入；存量电池保持，旧核爆按原档精确释放一次，达到 NA UPGRADE COMPLETE。两版均通过。
- 2.0.77 / 2.1.21 实际原型解析器分别验证：100,000 区域行动 repeat_count 可加载；4,294,967,296 被拒绝并明确报合法范围 0–4,294,967,295；衰减阈值 65,536 被拒绝并报范围 0–65,535。后两项是故意构造的 API 上限失败探针，不是生产 Mod 错误，日志在 tests/logs/prototype-limits。
- 所有 Lua 文件通过 Lua 5.2 语法检查，JSON 可解析；GUI 确认与一次性引爆逻辑通过 API doubles，未冒充真实 GUI 点击验收。

日志：tests/logs/final-20 或 final-21（acceptance、lifecycle、queue）；tests/logs/comparison-20 或 comparison-21 包含独立前后对照日志和 results.json；tests/logs/upgrade 保存旧版本迁移证据。

## 复现

    python3 tests/run.py --factorio /path/to/factorio --work /tmp/new-na-test-directory
    python3 tests/compare-performance.py --factorio /path/to/factorio --baseline /path/to/original-0.1.0-or-0.1.1 --work /tmp/new-comparison-directory
    python3 tests/upgrade.py --factorio /path/to/factorio --baseline /path/to/original-version --work /tmp/new-upgrade-test-directory
    lua5.2 tests/gui-unit.lua control.lua

queue 套件需要本地 UDP socket，用于仅绑定 127.0.0.1 的短暂保存测试服务器；2.0 / 2.1 使用独立端口 34290 / 34291。无网络权限的环境可以单独运行 acceptance、lifecycle，队列中途保存测试不能冒称完成。

## 限制与范围

- 生成额度只适用于本 Mod 的两道主要伤害波，不改变原版核弹。中心和附加视觉/环境效果仍在引爆时执行；大量建筑同帧死亡可能产生额外视觉峰值。
- 连锁总量越大，排队越久；在途弹道、伤害与场景实体数量仍有真实成本，不保证 60 UPS、无内存上限或无限规模安全。
- 经验单位面积伤害多随机种子统计、图形客户端流畅度、真实 GUI、多人客户端和任意第三方 Mod 的兼容性仍未验收。
- 本次聚焦核爆；独立评审中的严格雷达能源来源及约 4.7 MW 外部供电保留方案尚未实施，当前仍继承共享电网雷达。
- 本次没有合并 item-with-tags 实验，回收防刷电机制仍与 0.1.0/0.1.1 相同；现有主/辅助实体名称未改变。旧版已存在的在途弹道由引擎继续处理，无法回溯拆分。旧存档配置升级已实际验证已有电池及未命中载体，但没有把它宣称为完整多版本迁移矩阵测试。
