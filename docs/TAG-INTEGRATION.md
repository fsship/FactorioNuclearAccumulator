# 精确电量标签正式整合与测试

测试日期：2026-10-09。安装包为 `releases/nuclear-accumulator_0.2.0.zip`（Factorio 2.0.77 stable）和 `releases/nuclear-accumulator_0.2.1.zip`（2.1.21 experimental）。2.1.21 来自官方 experimental 通道，不能称为本次验证的 2.1 稳定版。两个安装包均直接参与了真实引擎回归，没有仅用源码目录代替最终 ZIP。

## 实现与范围

用户明确选择 tag，并说明尚无人运行该 Mod，因此不要求存档迁移。新版本只有一种 `item-with-tags` 物品和一种可见主建筑；旧的 `nuclear-accumulator-used` 原型、旧载体补迁移和光标状态备用读取不包含在新版本中。历史版本及实验源码保留用于对照，不是新版本的迁移路径。

- 配方制造的物品无 `na-energy-joules` 标签，首次放置得到 36 GJ。
- 玩家/机器人采矿时，在实际结果物品上保存真实 `LuaEntity.energy`，单位 J；使用浮点数原值，不舍入为整数 MJ。
- 重新放置读取实际消耗物品的标签，恢复到原生 accumulator。明确的零标签保持空电。
- 只有确认消耗的是无标签的新物品，才应用出厂电量。普通玩家/机器人事件无法识别消耗物品时从零开始；非法标签从零开始，有限数值限制在容量范围内。
- 每个物品独占一格，防止合并不同余电。蓝图不复制电量，所有状态请求同一种物品，可以用回收品填充同一个虚影。
- 保留既有原生电网、电路、雷达、手动确认、死亡核爆和分帧调度。雷达的消费者缓存不写入物品，采矿会丢弃这部分少量缓存能量。
- 脚本显式创建/复活全新建筑且无消耗物品时，仍按出厂满电初始化。管理员/其他 Mod 脚本需自行保证物品和能量守恒；这不等于正常回收能反复充满。

无旧存档迁移不影响正常的新版本存档保存/读取。配置修复不会给已登记的电池重新注电。核爆算法与 0.1.2/0.1.3 相同，`prototypes/explosions.lua` 字节不变：仍保留满电两道各 100,000 个伤害弹道、全局每 tick 最多调度 1,024 个新弹道、持久轮询队列和原生传播。

原生电池充放电实测为 `5,000,000.0001526 J/s`，尾数来自浮点运算。雷达短窗包含消费者缓存初始化差异，因此约为 `300,166.66666794 J/s`；没有把这一短窗差异当成无限能源或新的额定功率。总输出 5 MW 包含共享电网雷达在其中获得的功率；本版未实现严格仅本电池供能或为雷达预留固定 300 kW 的独立路径。

示例：三个回收物品的标签在实际物流箱内为 `{0, 12344150566.666809, 35989199916.66748}` J；机器人重建时新的真实电池逐个等于消耗的标签原值。三个额外回收循环再次检查没有余电增加。服务器保存发生在 tick 2400，届时机器人已完成前三次采矿，部分放电的源电池仍有效；加载后继续原生蓝图和回收流程，而不是重新手工造一组测试物品。

## 未完成项与限制

- 真实图形客户端的玩家放置/采矿、GUI 交互和外观、中文/英文布局，以及实际多人玩家会话仍未验收。玩家 `consumed_items` 分支、精确采矿序列化、非法/缺失标签和确认状态机有 API doubles 逻辑验证；真实机器人全程使用引擎事件，没有用人工事件冒充机器人。
- 严格“内置雷达只扣本电池，即使存在外部发电”及饱和负载下固定保留约 4.7 MW 外部供电尚未实现。本次保持并公开共享电网行为；参见 [DECISIONS.md](DECISIONS.md)。
- 单位面积密度由原生机制及 `round(N0×M²)`、单次伤害/类型/局部半径/速度/衰减检查保障，未做多随机种子、大规模阵列的经验密度统计。链式回归明确证明满电源 + 空电次级站的二次爆炸，未穷尽所有次级电量组合。
- 跨地表搬运、完整品质/DLC 和其他 Mod 组合没有全面验证。原生事件之外，第三方脚本自行生成物品或建筑的能量守恒由调用方负责。
- 旧存档迁移按用户明确指示不在范围内，不应作为未实现而隐藏的功能。
