# 单一源码与构建目标

2026-10-10 按用户要求整理仓库。当前 Mod 版本统一为 0.2.4，Factorio 2.0 和 2.1 共享运行源码，不为每次迭代复制目录。

```text
mod/                         唯一 Mod 运行源码、默认清单、使用说明
tests/                       一份共享测试运行器、场景及 GUI 逻辑检查
scripts/package.py           共用的 ZIP 构建模块和命令行入口
scripts/build-targets.json   两个游戏目标的清单兼容字段
releases/factorio-2.0/        2.0 安装包
releases/factorio-2.1/        2.1 安装包
test-results/                分版本/目标保存的原始证据
docs/                        项目决策、需求、报告
work/                        被 Git 忽略的测试存档、临时工作树
```

版本号只由 `mod/info.json` 决定。默认清单用于 2.0；打包时按构建目标覆盖 `factorio_version` 和 `dependencies`，两个目标的 Lua、本地化及其余运行文件完全相同。打包不写入源码，不生成持久源码副本；版本化的目录名仅存在于安装 ZIP 内。输出包同名、位于固定游戏目标目录，安装时选择相应目标。

从任何工作目录运行下列脚本，其默认源码和输出均相对仓库定位：

```sh
python3 scripts/package.py
python3 scripts/package.py --target 2.1
python3 scripts/package.py --output work/package-check
```

默认生成两个目标并更新输出目录的 `SHA256SUMS.txt`。`--source` 可显式指定另一个源码路径，主要用于独立工作树/构建验证。所有包使用固定 ZIP 元数据，内容不变时可复现相同字节。测试运行器导入同一打包模块，并可直接验收指定发布 ZIP；详见 [tests/README.md](../tests/README.md)。

8 个历史版本源码目录及 2 个实验源码副本从当前树删除，历史内容完整保留于 Git 快照 `a67c4ca`。9 个既有 ZIP 未重打包；118 个既有证据文件按 SHA-256 验证后移动到 [test-results/](../test-results/README.md)。历史报告仍记录原版本结论，并补充新证据路径/快照说明。

运行 `.lua`、本地化及现有测试场景的逻辑与 0.2.2/0.2.3 一致。此次变更的功能边界是目录和构建/测试入口：不修改储能、标签、供电、雷达、信号、GUI 或核爆。已知雷达共享电网和图形客户端验收限制继续适用。

| --- | --- | --- |
| acceptance：电网、0/50/100% 核爆、友军/连锁精确数量、传播和信号 | 通过 | 通过 |
| lifecycle：真实机器人建造/回收/重建、雷达、实际采矿和清理 | 通过 | 通过 |
| tags：精确/零标签、重复回收、真正配方产物、蓝图线路 | 通过 | 通过 |

| queue：全局额度、精确总数、阵营合并、地表删除 | 通过 | 通过 |
| queue：爆炸中途实际服务器保存/读取，最终数量一致 | 通过 | 通过 |

另从仓库外工作目录调用共享测试脚本，不传安装包，由同一打包模块自动生成 2.1 包并完成原生 lifecycle。静态核对包括：

- `mod/` 的 Lua 和本地化与 Git 快照 `a67c4ca` 最新 2.0/2.1 实现逐字节一致。
- 全部 Lua 5.2、JSON、Python 语法检查通过；原有 GUI/电量路径 API doubles 通过，没有把它称为图形客户端验收。
- 两版 ZIP 仅 `info.json` 中游戏版本/基础依赖不同，统一 Mod 版本号与其他文件一致。
- 从仓库内/外重复构建得到相同 SHA-256；源码不被构建改写。
- 118 个旧证据文件和 9 个旧 ZIP 校验值保持一致；当前本地 Markdown 链接有效。

原始日志和机器可读结果见 [test-results/releases/0.2.4/](../test-results/releases/0.2.4/)。这次回归验证新的目录与打包/测试入口，没有开展新的性能前后对比、客户端视觉验收或旧存档迁移。
